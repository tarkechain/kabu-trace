# 実装

対象: $ARGUMENTS （タスク番号。空の場合は未完了の最上位タスク1件）

## 厳守

- 1回の実行で着手するタスクは1件のみとする。複数をまとめて実装しない。
- docs/tasks.md に記載のない作業を行わない。必要だと判断した場合は、実装せず提案する。
- 色・サイズ・フォントは docs/design-tokens.md の値のみを使用する。直書きしない。
- 依存パッケージを無断で追加しない。

## 手順

1. docs/tasks.md を読み、対象タスクとその依存タスクの完了状況を確認する。依存が未完了であれば、その旨を報告して停止する。

2. 対象タスクに対応する要件（docs/requirements.md の該当番号）と、関係する design-tokens の項目を読む。

3. 実装方針を3行以内で述べる。方針に判断の分岐がある場合は、実装せず選択肢を提示して停止する。

4. 実装する。

5. 検証する。
   - CLAUDE.md に記載のビルドコマンドを実行し、成功することを確認する
   - 対象タスクの完了条件を満たしているか確認する
   - 対応する要件の受け入れ基準を満たしているか確認する
   - 視覚に関わる変更の場合、可能であれば描画結果を取得し、design-tokens.md の指定と照合する

6. docs/tasks.md の該当タスクにチェックを入れる。

7. 以下の形式で報告する。

```
## 完了: {{タスク番号}} {{タスク名}}
- 変更ファイル: {{一覧}}
- 検証結果: {{実行したコマンドと結果}}
- 要件 {{R-x.x}}: {{満たしている / 部分的（理由）}}
- 確認方法: {{利用者が自分で確認する手順を1〜3行で}}
- 残課題: {{なければ「なし」}}
```

8. コミットは1タスク1コミットとし、メッセージに対応する要件番号を含める。

9. 次のタスクへ自動的に進まない。停止して指示を待つ。

## 失敗時の扱い

同一タスクで2回連続して検証に失敗した場合、修正を重ねずに停止する。原因の分析と、要件側に問題がある可能性の指摘を報告する。

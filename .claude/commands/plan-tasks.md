# タスク生成

## 厳守

- このコマンドではコードを書かない。docs/tasks.md の生成・更新のみを行う。
- 要件定義書に記載のない作業をタスクに含めない。

## 前提

/audit を実行し、重大な指摘が0件であること。未実施の場合は、先に /audit を実行するよう促して停止する。

## 手順

1. docs/requirements.md、docs/design-tokens.md、CLAUDE.md を読む。

2. 要件を実装単位へ分解する。分解の基準は以下。
   - 1タスクは、単独で完了判定が可能であること
   - 1タスクの成果物は、原則として1〜3ファイルに収まること
   - 依存関係が一方向であること（相互依存するタスクは1つにまとめる）
   - 各タスクに、対応する要件番号を付すこと

3. タスクを依存順に並べ、フェーズへ区切る。フェーズの既定構成は以下とするが、案件に応じて調整してよい。
   - フェーズ1: 基盤（プロジェクト初期化、ディレクトリ構成、デザイントークンのCSS変数化）
   - フェーズ2以降: 機能単位。優先度の高い要件から順に、各フェーズ完了時点で動作確認可能な状態になるよう区切る
   - 最終フェーズ: 検証と仕上げ

4. 触るファイルが重複しないタスクには (P) を付す。

5. 要件カバレッジ表を作成し、すべての要件番号がいずれかのタスクに割り当てられていることを確認する。割り当て先のない要件があれば、タスクを追加するのではなく、その事実を報告する。

6. docs/tasks.md を上書きし、生成結果の要約（フェーズ数、タスク数、未カバーの要件）を報告して停止する。実装には進まない。

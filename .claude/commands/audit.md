# 整合性検査

## 厳守

- このコマンドは読み取り専用である。いかなるファイルも変更しない。
- 検出した問題を修正してはならない。報告のみを行う。

## 手順

1. 以下をすべて読む。
   - CLAUDE.md
   - docs/requirements.md
   - docs/design-tokens.md
   - docs/tasks.md （存在する場合）

2. 次の観点で検査する。

   - 未決: {{ }} 形式のプレースホルダが残っていないか
   - 矛盾: 文書間で両立しない記述がないか（例: スコープ外の機能が要件に含まれている、要件の数値と design-tokens の数値が食い違う）
   - 曖昧: 受け入れ基準が検証不能な表現になっていないか（判定者によって合否が変わる文言）
   - 網羅性: 第3.1節のやることが、すべて第6章の要件として展開されているか
   - 追跡可能性: 第10章の受け入れチェックリストが、第6章・第7章のすべての要件を覆っているか
   - 実現性: 第8章の制約と矛盾する要件がないか
   - EARS記法の妥当性: 第6章・第7章の各項目が WHEN 条件 THE SYSTEM SHALL 挙動 の形式に従い、かつ条件と挙動が客観的に判定可能か

3. 結果を以下の形式で報告する。

```
## 検出結果
重大 {{n}}件 / 中 {{n}}件 / 軽微 {{n}}件

### 重大（このまま実装すると手戻りが発生する）
1. [矛盾] {{内容}}
   該当: {{ファイル 第x章}} と {{ファイル 第y章}}
   対処案: {{}}
```

4. 重大が0件の場合のみ、実装に進んでよい旨を述べる。1件以上ある場合は、/kickoff による解消を促して停止する。

## 判定基準

- 重大: 実装の方向性が分岐する、または成果物が受け入れられない可能性がある
- 中: 実装は進むが、後で修正が必要になる可能性が高い
- 軽微: 表記の不統一など、成果物に影響しない

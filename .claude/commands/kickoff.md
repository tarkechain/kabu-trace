# 要件の壁打ち

対象: $ARGUMENTS （空の場合は要件定義書全体）

## 厳守

- このコマンドの実行中、コードを一切書かない。ファイルの作成・編集は docs/ 配下の文書に限る。
- 推測で埋めない。不明な点は必ず質問として返す。
- 一度に質問するのは最大5件まで。まとめて大量に聞かない。

## 手順

1. 以下を読む。
   - CLAUDE.md
   - docs/requirements.md
   - docs/design-tokens.md

2. 次の3種を検出し、重要度順に整理する。
   - 欠落: {{未定}} のまま残っている項目、および記載自体がない項目
   - 曖昧: 実装者によって解釈が割れる記述（「見やすく」「適度に」等、数値や基準のない表現）
   - 矛盾: 文書内または文書間で両立しない記述

3. 検出結果を、以下の形式で最大5件まで質問として提示する。重要度は「これが未確定だと後続の判断が連鎖的に止まる度合い」で判定する。

```
Q1. [欠落/曖昧/矛盾] {{論点}}
   該当箇所: {{ファイル名 第x章}}
   なぜ必要か: {{これが決まらないと何が決められないか}}
   選択肢:
     A. {{案}} — 利点 {{}} / 欠点 {{}}
     B. {{案}} — 利点 {{}} / 欠点 {{}}
   推奨: {{A または B}}。理由は {{}}。
```

4. 利用者の回答を受けたら、その内容を該当文書の該当箇所へ反映する。反映は指定箇所のみとし、他は変更しない。判断の経緯が残す価値のあるものであれば docs/decisions.md にも追記する。

5. 反映後、残っている未決項目の件数を報告し、次の5件を提示する。未決がゼロになるまで繰り返す。

6. 未決がゼロになったら、その旨を報告し、/audit の実行を促して停止する。

## 質問設計の方針

- 「どうしますか」と丸投げしない。必ず選択肢と推奨案を添える。利用者は専門知識を持たない前提で、各選択肢の帰結を具体的に示す。
- 視覚に関する論点は、言葉ではなく数値または参照物で確定させる。「落ち着いた色」ではなく具体的なHEX値の候補を提示する。
- 利用者が「任せる」と答えた場合は、推奨案を採用して文書へ反映し、採用した旨と理由を docs/decisions.md に記録する。

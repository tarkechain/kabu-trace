# 受け入れ検証

対象: $ARGUMENTS （空の場合は受け入れチェックリスト全項目）

## 厳守

- このコマンドではコードを修正しない。検証と報告のみを行う。
- 判定は客観的な根拠に基づく。実行したコマンドの出力、取得した描画結果、確認した値を示さない判定は行わない。

## 手順

1. docs/requirements.md 第10章の受け入れチェックリスト、第6章・第7章の要件、docs/design-tokens.md を読む。

2. 各項目を以下の方法で検証する。
   - 自動判定可能なもの: ビルド、Lint、テスト、リンク切れ、メタタグの有無などをコマンドで確認する
   - 描画に関わるもの: 指定された画面幅で描画結果を取得し、横スクロールの有無、コントラスト比、フォント、余白を design-tokens.md の値と照合する
   - 判定不能なもの: 「自動判定不能」として、利用者が目視で確認すべき手順を提示する

3. 結果を以下の形式で報告する。

```
## 検証結果
合格 {{n}} / 不合格 {{n}} / 判定不能 {{n}}

### 不合格
- {{R-x.x}} {{要件文}}
  実測: {{}}
  期待: {{}}
  推定原因: {{}}

### 判定不能（目視確認を依頼）
- {{N-x.x}} {{要件文}}
  確認手順: {{1〜3行}}
```

4. 不合格がある場合、修正は行わず、docs/tasks.md へ修正タスクとして追記してよいか確認して停止する。

## 注意

要件そのものが誤っている可能性を排除しない。実装が要件を満たしているが結果が不適切である場合、それは実装の不具合ではなく要件の不備である。その場合は要件側の見直しを提案する。

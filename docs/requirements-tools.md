## 1. 目的と背景

- 追加する目的: 閲覧数向上策として、株主優待マップ統合とキャッシュニュートラルPER計算ツールをKabuTraceに追加する。
- 完成したと言える条件:
  1. ツールハブと2ツール（株主優待マップ、キャッシュニュートラルPER計算ツール）が公開されている
  2. 株主優待マップで2社・全327店舗（サンマルク68店舗＋ヴィア・ホールディングス259店舗）が距離順表示・業態フィルタ可能な状態で表示される
  3. PER計算ツールで6項目を入力すると3つの計算結果（ネットキャッシュ・ネットキャッシュ比率・キャッシュニュートラルPER）が表示される
  4. 統合ページ・個別会社ページの両方で地図上に店舗がピン表示され、OpenStreetMapの帰属表示が維持されている
- 公開後に測る指標: Google Search Consoleを導入し、検索経由の閲覧数（表示回数・クリック数・検索語）を確認する。既存スコープのD-10（指標を測らない）とは異なる決定だが、本スコープ固有の上書き（docs/decisions.md [tools]D-12参照）。サイトへのスクリプト設置は不要でドメイン所有権確認のみで利用できるため、N-6.2（外部スクリプト禁止）には抵触しない。

## 2. 想定利用者と利用文脈

- 主たる利用者: 既存スコープD-1（外部の読者・投資家向け）を継承する
- 利用状況・デバイス比率・前提知識: 既存スコープD-9（スマホ7:デスクトップ3、投資基本用語を知っている個人投資家）を継承する
- SEO方針: 株主優待マップの各社ページは「会社名＋株主優待」の固有名詞検索を意識する（利用者指定・確定）

## 3. スコープ

### 3.1 やること
- /tools/ ハブページ（各ツールへのカード状リンク一覧。リスト形式で拡張しやすい構造）
- /tools/yutai-map/ 株主優待マップ（サンマルクホールディングス・ヴィア・ホールディングス〈7918〉の優待対象店舗リストJSON・距離順表示・業態フィルタ付きビューアをAstro構成へ移植・統合。地図描画はLeaflet.jsを自リポジトリに同梱して使用）
- /tools/per-calculator/（仮称）キャッシュニュートラルPER計算ツール（清原達郎『わが投資術』のネットキャッシュ比率・キャッシュニュートラルPER算出ロジック、手入力方式、同一オリジンの自作JavaScriptによる即時計算）
- グローバルナビゲーションへの「ツール」リンク追加

### 3.2 やらないこと
- サンマルクホールディングス・ヴィア・ホールディングス以外の会社データの追加
- PER計算ツールの複数銘柄比較・入力履歴の保存機能
- 株主優待マップの現在地取得以外の検索方法（駅名検索等）

### 3.3 非目標
- 全上場企業の株主優待制度の網羅
- PER計算結果の履歴保存

第3.2節と第3.3節は省略しないこと。記載がない領域では実装が過剰になる。

### 4.2 ページ構成

#### T-1 ツールハブ
カードは追加順（株主優待マップ→キャッシュニュートラルPER計算ツール）で表示する。1カードにはツール名・一言概要・遷移ボタンのみを配置し、画像は持たない（ハブページの実装は軽量に留める）。

#### T-2 株主優待マップ
地図表示（Leaflet.js）とリスト+フィルタを併用する。距離順表示の基準地点はブラウザのGeolocation APIによる現在地取得とし、利用者が許可しなかった場合は登録順（既存データの並び順）表示にフォールバックする。

#### T-3 株主優待マップ個別会社ページ
上から順に: ①会社名・証券コード ②地図（Leafletによるピン表示）＋店舗一覧（距離順表示・業態フィルタ付き。地図のピン表示は一覧の絞り込み・並べ替えと連動する） ③出典クレジット・基準日（ページ末尾）。移植元の既存ビューア（会社ごとに地図＋店舗一覧を持つ単体HTML）の構成を継承し、統合ページ（T-2）と同様に地図を持たせる。OpenStreetMapの帰属表示は地図上に常時表示する（第6章T-3.6、第8章参照）。

#### T-4 キャッシュニュートラルPER計算ツール
流動資産・棚卸資産・投資有価証券・負債合計・時価総額・当期純利益の6項目を1画面の縦一列フォームに配置する。送信ボタンは設けず、入力ごとに即時再計算する。結果は「ネットキャッシュ」「ネットキャッシュ比率」「キャッシュニュートラルPER」の3値をカード形式で表示する。

### 4.3 ナビゲーション
- グローバルメニュー: 既存の「開示まとめ」「銘柄分析」「blog」の末尾に「ツール」を追加する（開示まとめ・銘柄分析・blog・ツール）

## 5. コンテンツ

- 株主優待マップのデータ供給元: 既存プロジェクトのローカルファイルを移植する。
  - サンマルクホールディングス: `~/Downloads/Saintmarc_yutai_artifacts/saintmarc_yutai_stores.json`（68店舗、東京23区、schema_version 1）、`saintmarc_yutai_map.html`（Leaflet.js 1.9.4使用の既存ビューア）
  - ヴィア・ホールディングス（証券コード7918）: `~/Downloads/Via_holdings_yutai_artifacts/via_holdings_yutai_ledger.json`（259店舗、全国、schema_version 1）、`via_holdings_yutai_map.html`（同上）
  - 両JSONとも `stores` 配列の下に個別店舗を持つ構造で、トップレベルに `schema_version` / `generated_at` / `scope` / `rate_source` / `notes` のメタ情報を持つ（ヴィアのみ `company` / `ticker` も持つ）。移植時にこのメタ情報も保持する。
- データスキーマ: 対象会社が今後増える前提の汎用スキーマとする。
  - 会社単位のメタ情報に `slug`（URLの命名に使う会社名のローマ字表記。例: `saintmarc`, `via-holdings`）を明示的なフィールドとして持たせる。自動変換（会社名からの自動生成）には頼らず、会社追加時に個別に確定する
  - 会社固有の項目は元データのフィールドをそのまま採用する: サンマルクは `id / brand / rate / name / ward / address / lat / lng / checked`、ヴィアは `id / company / brand / name / address / tel / lat / lng / place_id / rate / notes / checked`
  - `rate` は表示形式が会社間で異なる（サンマルクは数値%、ヴィアは文字列）ため、汎用スキーマでは表示用文字列 `rate_label`（必須）を設け、%として扱える場合のみ数値項目 `rate_percent` を追加で持たせる
  - `ward`（サンマルク）、`company` / `tel` / `place_id` / `notes`（ヴィア）等の会社固有フィールドはオプショナル項目として汎用スキーマに吸収する
- キャッシュニュートラルPER計算ツールの計算式・入力項目（清原達郎『わが投資術』の手法、利用者確認済み）:
  - ネットキャッシュ ＝ 流動資産 − 棚卸資産 ＋ 投資有価証券×0.7 − 負債合計
  - ネットキャッシュ比率 ＝ ネットキャッシュ ÷ 時価総額
  - キャッシュニュートラルPER ＝ (時価総額 − ネットキャッシュ) ÷ 当期純利益
  - 入力項目: 流動資産・棚卸資産・投資有価証券・負債合計・時価総額・当期純利益（6項目）
  - {{未定: 棚卸資産控除の要否。書籍原本での確認が取れるまで未定とし、暫定的には控除ありの上記の式で進める}}
- 初期投入する会社数・店舗データ件数: サンマルクホールディングス（68店舗）、ヴィア・ホールディングス（259店舗）の2社（確定。第4節Q4参照）

## 6. 機能要件

形式は docs/requirements.md 第6章と同じ（EARS記法）。

### T-1 ツール一覧表示
ユーザーストーリー: 訪問者として、公開中のツール一覧を見て、使いたいツールへ移動できる。理由は目的のツールを探すため。

受け入れ基準:
- T-1.1 WHEN 訪問者が/tools/を開く THE SYSTEM SHALL 公開中の全ツールをカード形式で追加順に表示する
- T-1.2 WHEN 訪問者がカードを押す THE SYSTEM SHALL 対応するツールページへ遷移する
- T-1.3 THE SYSTEM SHALL グローバルナビゲーションに「ツール」リンクを表示する

### T-2/T-3 株主優待マップ表示
ユーザーストーリー: 訪問者として、株主優待の対象店舗を地図・距離順・業態で確認できる。理由は自分が使える優待店舗を探すため。

受け入れ基準（T-2: 統合ページ /tools/yutai-map/、2社合算）:
- T-2.1 WHEN 訪問者が/tools/yutai-map/を開く THE SYSTEM SHALL 2社の店舗一覧を表示する
- T-2.2 WHEN 訪問者が位置情報の取得を許可する THE SYSTEM SHALL 現在地からの距離順に店舗を並べ替える
- T-2.3 WHEN 訪問者が位置情報の取得を許可しない、または取得に失敗する THE SYSTEM SHALL 登録順で店舗一覧を表示する
- T-2.4 WHEN 訪問者が業態フィルタを選択する THE SYSTEM SHALL 選択した業態の店舗のみを表示する
- T-2.5 WHEN 訪問者が/tools/yutai-map/を開く THE SYSTEM SHALL 表示対象の店舗をLeafletベースの地図上にピン表示する
- T-2.6 WHEN 距離順並べ替えまたは業態フィルタにより表示対象の店舗が変化する THE SYSTEM SHALL 地図上のピン表示を表示対象に連動して更新する
- T-2.7 THE SYSTEM SHALL 地図上に「© OpenStreetMap contributors」の帰属表示を常時表示し、これを削除しない

受け入れ基準（T-3: 個別会社ページ /tools/yutai-map/{slug}/、1社のみ）:
- T-3.1 WHEN 訪問者が個別会社ページを開く THE SYSTEM SHALL その会社の店舗一覧・出典クレジットを表示する
- T-3.2 WHEN 訪問者が位置情報の取得を許可する THE SYSTEM SHALL 現在地からの距離順に店舗を並べ替える（許可しない場合はT-2.3と同様に登録順表示）
- T-3.3 WHEN 訪問者が業態フィルタを選択する THE SYSTEM SHALL 選択した業態の店舗のみを表示する
- T-3.4 WHEN 訪問者が個別会社ページを開く THE SYSTEM SHALL その会社の店舗をLeafletベースの地図上にピン表示する
- T-3.5 WHEN 距離順並べ替えまたは業態フィルタにより表示対象の店舗が変化する THE SYSTEM SHALL 地図上のピン表示を表示対象に連動して更新する
- T-3.6 THE SYSTEM SHALL 個別会社ページの地図上に「© OpenStreetMap contributors」の帰属表示を常時表示し、これを削除しない

### T-4 キャッシュニュートラルPER計算
ユーザーストーリー: 訪問者として、財務数値を入力してキャッシュニュートラルPERを即時に算出できる。理由は銘柄の実質的な割安度を自分で確認するため。

受け入れ基準:
- T-4.1 WHEN 訪問者が6項目（流動資産・棚卸資産・投資有価証券・負債合計・時価総額・当期純利益）のいずれかに数値を入力する THE SYSTEM SHALL ネットキャッシュ・ネットキャッシュ比率・キャッシュニュートラルPERを即時に再計算して表示する
- T-4.2 WHEN 入力欄が空、または数値として解釈できない場合 THE SYSTEM SHALL 計算結果の代わりに未入力である旨を表示する（エラー表示にしない）

## 7. 非機能要件

- SEO: 株主優待マップの各社ページは固有のtitleタグを持つ（確定。既存スコープN-5.1の延長）
- 既存スコープのN-1〜N-7（レスポンシブ・対応環境・性能・アクセシビリティ・セキュリティ・保守性）を本スコープにもそのまま適用する。異なる要件が必要な場合のみ個別に上書きする（N-6.2の解釈整理は上記「クライアントサイドJSの導入」を参照）
- クライアントサイドJSの導入: PER計算ツールおよび株主優待マップの距離順表示・フィルタは、同一オリジンから配信する自作JavaScriptで実現する。既存スコープのN-6.2「外部スクリプトを使用しない」は外部ドメインからのスクリプト読み込みを禁止する趣旨であり、同一オリジンの自作JSはこれに抵触しないと整理する（docs/decisions.md [tools]D-1参照）。
- 地図描画ライブラリ: 既存ビューアはLeaflet.js 1.9.4をCDN（cdnjs）経由で読み込んでいる。本スコープではLeaflet.js本体を自リポジトリに同梱し、同一オリジンから配信することでスクリプト面はN-6.2を満たす。背景地図タイル（OpenStreetMapタイルサーバー）は画像アセットであり外部依存を許容する。タイル取得に失敗した場合でも、店舗の一覧表示・距離順ソート・業態フィルタは機能するようフォールバックを維持する（既存実装を継承）。

## 8. 制約

- 技術的制約: 既存のAstroサイト構成に統合する。株主優待マップは既存資産をJSONデータとして移植する。
- データ出典の表記: 各社ページに「出典: 各社公式サイト掲載の株主優待制度ページ（基準日）」等のクレジットと、座標データの注記（Google Maps/Places検索により付与）を掲載する（既存データの`rate_source`・`notes`を引き継ぐ）。
- 地図タイルの帰属表示（必須）: 背景地図タイルにOpenStreetMapを使用するため、ODbL（Open Database License）上の要件として「© OpenStreetMap contributors」の帰属表示をLeafletの既定表示のまま維持する。
- デプロイ先の制約: 既存スコープと同じ（GitHub Pages、ベースパス /kabu-trace/）を継承する
- 予算: 既存スコープD-3を継承し0円（GitHub Pages無料枠、独自ドメインは取得しない）
- 期限: 特に定めない

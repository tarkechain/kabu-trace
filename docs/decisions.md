# 決定記録

要件が「なぜそうなったか」を記録する。requirements.md には結論のみを書き、経緯はここに残す。
この文書は毎回読ませる必要はない。判断を蒸し返すときと、後任へ引き継ぐときに参照する。

記入形式:

```
## D-{{番号}} {{論点}}
- 日付: {{YYYY-MM-DD}}
- 決定: {{採用した内容}}
- 理由: {{なぜそれを選んだか}}
- 却下した案: {{案と、却下した理由}}
- 影響範囲: {{関連する要件番号}}
- 再検討の条件: {{この前提が崩れたら見直す、という条件}}
```

## D-1 主たる利用者
- 日付: 2026-09-23
- 決定: 外部の読者・投資家向けの情報発信を主目的とする
- 理由: プロジェクト概要に将来のアフィリエイトページ追加が明記されており、収益化を見込むなら最初から外部読者向けの設計にした方が手戻りが少ない。/kickoff で利用者に確認し「任せる」との回答を得たため推奨案を採用。
- 却下した案: 自分用の記録・学習ログが主目的 — 初期コストは低いが、後からアフィリエイト用に読者向け設計へ作り直す手間が生じる
- 影響範囲: requirements.md 第2章
- 再検討の条件: アフィリエイト展開を取りやめる場合

## D-2 技術スタック
- 日付: 2026-09-23
- 決定: Astro を採用する（既存プロジェクト my-site と同一パターン。開示情報・銘柄分析・blogを独立したContent Collectionsとして扱う）
- 理由: 既存の知見を再利用できる。静的生成でJSが最小限になり「低脆弱性・低保守コスト」という技術目標に合致する。
- 却下した案: Next.js等の静的出力 — エコシステムは大きいが静的サイトの目的には過剰で、既存パターンと不一致になり保守コストが増える
- 影響範囲: CLAUDE.md 技術スタック
- 再検討の条件: なし（技術的な決定が変わったときのみ見直す）

## D-3 ホスティング先・公開URL
- 日付: 2026-09-23
- 決定: GitHub Pages で公開する。公開URLは https://tarkechain.github.io/kabu-trace/ 、ベースパスは /kabu-trace/
- 理由: 追加コストなしで既存my-siteと同一運用ができ、低保守コスト目標を満たす
- 却下した案: 独自ドメイン + Netlify/Vercel等 — ブランド性は高いが追加コスト・DNS設定が発生し目標と矛盾する
- 影響範囲: CLAUDE.md プロジェクト概要・技術スタック、requirements.md 第8章
- 再検討の条件: 独自ドメインが必要になったとき

## D-4 完成条件

- 理由: requirements.md の記入規則「検証可能な文で3項目以内」を満たし、/verify で直接検証可能な内容にした

## D-8 コンテンツの供給元・初期投入データ件数

## D-9 想定利用者の利用状況・デバイス比率・前提知識

## D-10 外部スクリプトの利用可否・アクセス解析
- 日付: 2026-09-23
- 決定: 外部スクリプトは使用しない。アクセス解析は導入せず、公開後の指標は測らない
- 理由: 要件から解析導入の必要性が読み取れず、厳守事項「依存パッケージを無断で追加しない」の精神に沿い、必要になった時点で個別に提案する方が安全

## D-11 一覧・個別ページ以外の機能要件

## [tools]D-1 クライアントサイドJSの導入（PER計算ツール・株主優待マップ）
- 日付: 2026-09-23
- 決定: PER計算ツールと株主優待マップの距離順表示・フィルタは、同一オリジンから配信する自作JavaScriptで実現する。既存スコープのN-6.2「外部スクリプトを使用しない」は外部ドメインからのスクリプト読み込みを禁止する趣旨と解釈し、同一オリジンの自作JSはこれに抵触しないと整理した
- 理由: 「計算ツール」「距離順表示」という機能の性質上、即時計算・並び替えにはクライアントサイドの処理が必要。外部CDNではなく自リポジトリ同梱にすることで、既存要件（N-6.2）と技術的に矛盾しない形にした
- 却下した案: 計算式の説明のみ掲載し電卓機能を持たせない — 「ツール」としての訴求力が弱く、閲覧数向上策という目的に合わない
- 影響範囲: docs/requirements-tools.md 第3章・第7章
- 再検討の条件: なし

## [tools]D-2 地図描画ライブラリ（Leaflet.js）の扱い

- 決定: 既存ビューア（saintmarc_yutai_map.html, via_holdings_yutai_map.html）が使用するLeaflet.js 1.9.4（cdnjs経由）を自リポジトリに同梱し、同一オリジンから配信する。背景地図タイル（OpenStreetMapタイルサーバー）は画像アセットとして外部依存を許容し、取得失敗時も一覧・距離順表示・業態フィルタは機能するフォールバックを維持する

- 却下した案: 地図表示自体を持たない — 既存資産の主要な価値（距離順表示・視覚的な把握）を損なう
- 影響範囲: docs/requirements-tools.md 第5章・第7章

## [tools]D-9 PER計算ツールの入力・結果表示方式
- 日付: 2026-09-23
- 決定: 流動資産・棚卸資産・投資有価証券・負債合計・時価総額・当期純利益の6項目を1画面の縦一列フォームに配置し、送信ボタンなしで入力ごとに即時再計算する。結果は「ネットキャッシュ」「ネットキャッシュ比率」「キャッシュニュートラルPER」の3値をカードで表示する
